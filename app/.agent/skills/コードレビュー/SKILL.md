# コードレビュースキル

このスキルは、コードの品質を多角的にレビューし、改善点を提案するためのガイドラインを提供します。特に Dockstring の原則に則った堅牢なコードか、日本語読者にとって見やすいかを重点的に評価します。

## レビューの重点項目

### 1. 堅牢性 (Robustness) - Dockstring 原則

コードが以下のように記述されているか確認してください：

#### エラーハンドリング
- エラーを適切にキャッチし、処理を継続・終了する判断が明確
- 例外が再帰的に伝わらないか
- リソースの解放が適切に行われるか（try/finally, context managers）

```python
# 良い例
try:
    with open('file.txt') as f:
        data = f.read()
except FileNotFoundError:
    logger.error("ファイルが見つかりませんでした")
    return None
```

#### 境界条件の考慮
- 配列/リストのインデックスが有効範囲か
- 空の値、None 値、空文字列の扱いが明確
- 数値の範囲制限、入力値のバリデーション

#### 攻撃対策 (Security)
- SQLインジェクションの防止（パラメータ済みクエリ使用）
- ファイル名の注入防止（相対パスの確認）
- 機密情報のログ出力の回避

### 2. 可読性 (Readability) - 日本語読者にとって見やすいか

#### 命名規則
- 変数、関数、クラスの名称が意味を持っていて一目で目的が分かる
- 日本語ドキュメンテーションの存在と適切性
- 定数の命名が統一された規則に従っているか

```python
# 良い例（日本語コメント付き）
def calculate_total_price(price: float, quantity: float) -> float:
    """
    合計価格を計算する
    Args:
        price: 単価（円）
        quantity: 数量
    Returns:
        合計価格（円）
    """
    return price * quantity
```

#### コードの構造
- 関数が単一の責任を持つ（SRP）
- 関数の長さ、ネストの深さが適切（2-3 段が理想）
- 重複コードがないか（DRY 原則）

#### コーディングスタイルの統一
- インデント、空行、改行の規則性
- 一貫した命名規則（camelCase, snake_case など）

### 3. 保守性 (Maintainability)

- 複雑なロジックに注釈やドキュメンテーションがあるか
- 定数が魔法の数値として散在していないか
- 依存関係が明確で、カプセル化されているか

## レビューの優先度

### 高優先度（必ず修正）
1. セキュリティホール
2. データ破損の可能性があるバグ
3. アプリケーションがクラッシュする問題

### 中優先度（修正推奨）
1. 可読性を著しく低下させるコード
2. 保守性を損なう重複コード
3. エラーハンドリングの不備

### 低優先度（改善の余地）
1.  Naming の改善
2.  ドキュメンテーションの追加
3.  パフォーマンス最適化の可能性

## レポートフォーマット

レビュー結果を伝える際は、以下のフォーマットを使用してください：

```
## レビュー結果：[ファイル名]

### ⚠️ 高優先度問題
- [問題内容] - [修正提案]

### 🔧 中優先度問題
- [問題内容] - [改善案]

### 💡 改善提案
- [コードスタイルの改善提案]

### 👍 良い点
- [特筆すべき良い部分]

### 📝 まとめ
[全体の評価と推奨アクション]
```

## コードチェックリスト

レビュー時に以下の項目を確認：

- [ ] エラーハンドリングが網羅されている
- [ ] 境界条件が考慮されている
- [ ] セキュリティ上好ましくないパターンがない
- [ ] 変数/関数名に意味がある
- [ ] 日本語ドキュメンテーションが充実している
- [ ] 重複コードがない
- [ ] 一貫したスタイルが保たれている

## 例

**レビュー対象**: `user_auth.py`

```
## レビュー結果：user_auth.py

### ⚠️ 高優先度問題
- システムコマンドを直接実行 - 注入攻撃のリスク
```python
# 危険な例
os.system(f"echo {user_input} >> log.txt")
```

### 🔧 中優先度問題
- エラーハンドリングが不十分
- 変数名が曖昧

### 💡 改善提案
- 関数名を `process_user_input` に変更
- `context managers` を使用してリソース管理を改善

### 👍 良い点
- 日本語コメントが充実している
- 関数が単一の責任を持つ

### 📝 まとめ
セキュリティ上の問題が存在するため、優先的に修正を推奨します。
```

## Dockstring 原則の要約

- **エラーは逃さない**: 全てのエラー経路を考慮する
- **防御的プログラミング**: 入力値を常に疑う
- **明示的である**: 暗黙の前提を減らす
- **検証可能**: 結果の検証が容易なコードを書く

このスキルを使用する際は、建設的で具体的なフィードバックを心がけてください。
