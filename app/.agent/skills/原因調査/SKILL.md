# 原因調査スキル

このスキルは、技術的な問題やエラーの根本原因を特定し、分析するための体系的なアプローチを提供します。

## 調査プロセス

### 1. 現象の把握
- エラーメッセージ、ログ、症状の詳細を収集
- 問題が発生したタイミング、頻度、環境を明確化
- 影響範囲を特定（単一システムか全システムか）

### 2. 根本原因分析
原因を探る際には、以下の手法を組み合わせて使用してください：

- **5 Why 分析**: 原因を5回「なぜ？」と問い続ける
- **イシカワ図**: 人、物、環境などの要因を分類して整理
- **比較分析**: 正常時と不正常時の違いを明らかにする

### 3. 検証と対策
- 特定した原因が実際に問題を引き起こすことを検証
- 再発防止策、一時的措置、長期的対策を提案
- 対策の実装手順と確認方法を提示

## ログ分析のポイント

効率的な原因特定のために、以下のログを確認してください：

1. **アプリケーションログ**: エラー発生時刻、スタックトレース
2. **システムログ**: メモリ、CPU、ディスクの使用状況
3. **ネットワークログ**: 通信エラー、タイムアウト情報
4. **データベースログ**: 쿼リエラー、パフォーマンス指標

## 調査ツールの活用

状況に応じて以下のようなツール使用情况：

- `grep` / `findstr`: ログ内のキーワード検索
- `head` / `tail`: ログの先頭・末尾確認
- `awk` / `sed`: ログパターンの抽出と変換
- 専門ログ分析ツール: 構造化ログの可視化

## 出力フォーマット

調査結果を伝える際は、以下の構成を心がけてください：

```
## 問題の概要
[現象を簡潔に説明]

## 確認した事項
- [確認結果1]
- [確認結果2]

## 根本原因
[原因を明確に説明]

## 対策案
1. [即座に実施できる対策]
2. [中長期的な対策]

## 参考資料
[関連するログ、ドキュメントへのリンク]
```

## 例

**ユーザー**: 「サーバーが応答しなくなっています」

**回答例**:
```
## 問題の概要
先ほどからWebサーバーへの接続がタイムアウトしています。

## 確認した事項
- エラーログ：connection refused
- データベース：応答が遅延
- システムリソース：CPU使用率95%以上

## 根本原因
特定のクエリがデータベースを圧迫し、リソース枯渇が発生。

## 対策案
1. 問題のクエリを一時停止
2. サーバーのリソースを解放
3. クエリの最適化実施

## 参考資料
[database logs](/var/log/database.log)
```

## 注意点

- 仮説だけで結論を出さない
- 関連する全ての証拠を収集する
- 対策の効果を確認する

このスキルを使用する際は、必ず体系的かつ客観的なアプローチを心がけてください。
